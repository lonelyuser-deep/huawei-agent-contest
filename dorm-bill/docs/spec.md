# 宿舍账单管家 - 需求规格说明书 (SRS)

> 版本: 1.2.0  
> 更新日期: 2026-10-10  
> 变更: 整合「智能攒钱小助手」——储蓄目标 + 进度可视化 + 省钱建议联动

---

## 1. 项目概述

针对大学生宿舍生活中"水电杂费分摊易扯皮"、"生活账单记录繁琐"、"公共物品管理混乱"等痛点，本项目基于华为云 CodeArts 全生命周期软件开发服务，开发一款集 OCR 智能识别、NLP 语义记账、AI 决策推荐于一体的轻量级 Web 应用。

## 2. 核心功能需求

### 2.1 智能账单解析（OCR）[已有]

调用华为云 ModelArts 的 OCR 能力，一键提取电费、水费、外卖订单截图中的金额与明细。

### 2.2 NLP 语音/文字记账 [已有]

集成华为云 NLP 服务，支持自然语言输入自动识别语义、提取人名与金额并归类记账。

### 2.3 宿舍公平决策系统 [已有]

基于历史消费数据计算"宿舍公平度"，智能推荐最优分摊方案。

---

### 2.4 个人月度预算与超支预警 [新增]

#### 2.4.1 功能描述

用户可以设定每个月的总预算上限，系统实时计算本月已消费金额，并在消费接近或超过预算时发出预警。

#### 2.4.2 需求详述

| 编号 | 需求 | 优先级 |
|------|------|--------|
| B-001 | 用户可在"设置"页面设定月度总预算金额（如 1500 元） | P0 |
| B-002 | 系统实时计算本月已消费总金额 | P0 |
| B-003 | 首页显示预算进度条，直观展示已消费/预算比例 | P0 |
| B-004 | 消费达到预算 80% 时，首页顶部显示黄色警告条："本月预算即将耗尽" | P0 |
| B-005 | 消费超过预算 100% 时，显示红色警告条并弹窗提醒 | P0 |
| B-006 | 预算数据持久化存储，支持按月查看历史预算记录 | P1 |
| B-007 | 支持按类别分别设置预算（电费、水费、餐饮等） | P2 |

#### 2.4.3 验收标准

- ✅ 设置页面有预算输入框，可保存和修改月度预算
- ✅ 首页有预算进度条，实时反映当月消费比例
- ✅ 消费 ≥ 80% 预算时，黄色警告条可见
- ✅ 消费 > 100% 预算时，红色警告条 + 弹窗提醒
- ✅ 刷新页面后预算设置不丢失

### 2.5 AI 智能省钱建议 [新增]

#### 2.5.1 功能描述

基于用户的消费数据（如外卖频次、奶茶支出占比等），在首页生成个性化的省钱建议。初期使用规则引擎（硬编码逻辑），后期预留接口接入华为云 ModelArts 大模型。

#### 2.5.2 需求详述

| 编号 | 需求 | 优先级 |
|------|------|--------|
| S-001 | 首页增加"省钱小助手"卡片，展示 AI 生成的省钱建议 | P0 |
| S-002 | 基于消费数据生成建议（如外卖超 10 次提示"建议尝试食堂"） | P0 |
| S-003 | 建议内容包含：问题描述、具体建议、预计可省金额 | P0 |
| S-004 | 预留大模型接口，支持后续接入华为云 ModelArts 生成个性化建议 | P1 |
| S-005 | 支持用户反馈建议是否有用（点赞/点踩），用于优化建议质量 | P2 |

#### 2.5.3 规则引擎策略（初期硬编码）

| 条件 | 建议内容 | 预计可省 |
|------|---------|---------|
| 外卖 > 10 次/月 | "本月外卖较多，建议尝试食堂，经济又健康" | ¥200-400 |
| 奶茶/饮品占比 > 20% | "奶茶支出占比较高，建议减少频次或自制饮品" | ¥100-200 |
| 电费 > 同期平均 1.5 倍 | "本月电费偏高，建议检查电器使用习惯" | ¥50-100 |
| 夜宵/零食 > 5 次/月 | "夜宵频次较高，减少夜宵有益健康又省钱" | ¥100-300 |
| 总消费连续 3 月上升 | "消费呈上升趋势，建议制定月度消费计划" | - |

#### 2.5.4 验收标准

- ✅ 首页有"省钱小助手"卡片
- ✅ 根据消费数据生成至少 1 条建议（有数据时）
- ✅ 每条建议包含问题描述、建议内容、预计可省金额
- ✅ 无消费数据时显示友好提示
- ✅ 代码结构预留大模型接口

### 2.6 智能攒钱小助手 [新增·核心]

#### 2.6.1 功能描述

将"省钱建议"与"个人储蓄目标"整合为一个核心功能。用户设定储蓄目标（如买电脑 ¥3000），系统基于账单给出省钱建议，当用户采纳建议或当月消费低于预算时，自动将省下的钱算入储蓄进度，形成"省钱→攒钱"闭环。

#### 2.6.2 需求详述

| 编号 | 需求 | 优先级 |
|------|------|--------|
| G-001 | 用户可在"个人中心"设定储蓄目标（名称、金额、截止日期） | P0 |
| G-002 | 首页显眼位置展示"智能攒钱小助手"卡片，含目标、进度条、AI建议 | P0 |
| G-003 | 储蓄进度条实时显示进度百分比（已存/目标） | P0 |
| G-004 | 当月消费低于预算时，结余自动算入储蓄进度，提示"本月结余 ¥X，已加入储蓄" | P0 |
| G-005 | 用户采纳省钱建议后，预计可省金额按比例算入储蓄进度 | P0 |
| G-006 | 联动提示示例："这个月少喝了3杯奶茶，你的新电脑进度 +¥15！" | P0 |
| G-007 | 达成储蓄目标时触发弹窗祝贺 | P0 |
| G-008 | 支持多个储蓄目标，可切换当前活跃目标 | P1 |
| G-009 | 储蓄历史记录，可查看每月攒了多少钱 | P1 |

#### 2.6.3 联动逻辑详述

```
触发条件                          →  联动动作
─────────────────────────────────────────────────────
当月消费 < 预算                   →  结余 = 预算 - 消费，自动加入储蓄
                                     提示: "本月结余 ¥{结余}，已加入'{目标名}'进度！"

用户点击"采纳建议"                →  取建议预计可省金额的 50% 加入储蓄
                                     提示: "采纳省钱建议，{目标名}进度 +¥{金额}！"

特定类别消费减少（环比下降 >30%）  →  差额按比例加入储蓄
                                     提示: "这个月少喝了{N}杯奶茶，{目标名}进度 +¥{金额}！"

达成目标 (current >= target)      →  弹窗祝贺
                                     "🎉 恭喜！'{目标名}'储蓄目标已达成！"
```

#### 2.6.4 验收标准

- ✅ 可设定储蓄目标（名称、金额、截止日期）
- ✅ 首页有"智能攒钱小助手"卡片，含进度条
- ✅ 当月有结余时自动加入储蓄并提示
- ✅ 采纳省钱建议后储蓄进度增加
- ✅ 联动提示消息正确显示（含目标名和金额）
- ✅ 达成目标时弹窗祝贺
- ✅ 刷新后储蓄数据不丢失

## 3. 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NF-001 | 响应速度 | 预算计算 < 100ms，省钱建议生成 < 500ms |

| NF-003 | 可扩展性 | 省钱建议引擎支持插件式扩展，便于添加新规则 |
| NF-004 | 兼容性 | 预算进度条和警告条在移动端正常显示 |

## 4. 数据需求

### 4.1 新增数据表：budget_settings

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string (PK) | 记录 ID |
| userId | string | 用户 ID |
| monthlyBudget | number | 月度预算上限（元） |
| categoryBudgets | JSON | 按类别的预算设置 |
| alertThreshold | number | 预警阈值百分比（默认 80） |
| createdAt | number | 创建时间戳 |
| updatedAt | number | 更新时间戳 |

### 4.2 新增数据表：budget_records

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string (PK) | 记录 ID |
| userId | string | 用户 ID |
| year | number | 年份 |
| month | number | 月份 (1-12) |
| budget | number | 当月预算 |
| actualSpent | number | 实际消费 |
| status | string | normal / warning / exceeded |
| createdAt | number | 创建时间戳 |

### 4.3 新增数据表：savings_goals

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string (PK) | 记录 ID |
| userId | string | 用户 ID |
| goalName | string | 目标名称（如"买电脑"） |

| isActive | boolean | 是否为当前活跃目标 |
| status | string | active / completed / archived |
| createdAt | number | 创建时间戳 |
| updatedAt | number | 更新时间戳 |

### 4.4 新增数据表：savings_records

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string (PK) | 记录 ID |

| createdAt | number | 创建时间戳 |

## 5. 接口需求

### 5.1 预算管理接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 获取预算设置 | GET | /api/budget/settings | 获取当前用户的预算配置 |
| 更新预算设置 | PUT | /api/budget/settings | 更新月度预算上限 |
| 获取本月统计 | GET | /api/budget/current | 返回本月已消费、预算、比例、状态 |

### 5.2 省钱建议接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 获取省钱建议 | GET | /api/suggestions | 基于消费数据生成省钱建议列表 |
| 反馈建议 | POST | /api/suggestions/feedback | 用户对建议的反馈（有用/无用） |
### 5.3 储蓄管理接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 获取储蓄目标 | GET | /api/savings/goals | 获取所有储蓄目标列表 |
| 创建储蓄目标 | POST | /api/savings/goals | 创建新储蓄目标 |
| 更新储蓄目标 | PUT | /api/savings/goals/:id | 更新目标信息 |
| 删除储蓄目标 | DELETE | /api/savings/goals/:id | 删除储蓄目标 |
| 获取当前活跃目标 | GET | /api/savings/active | 获取当前活跃的储蓄目标及进度 |
| 手动存入 | POST | /api/savings/deposit | 手动向目标存入金额 |
| 计算月度结余 | GET | /api/savings/surplus | 计算本月预算结余并自动存入 |
| 采纳建议存入 | POST | /api/savings/adopt | 采纳省钱建议，将预计可省金额存入储蓄 |
| 获取储蓄记录 | GET | /api/savings/records | 获取储蓄历史记录 |
